# 驱力系统设计笔记

给 bot 加"本能"的心跳决策系统。学术名字：**驱力还原 + 稳态反馈的效用行为选择**
（drive reduction / homeostatic utility-based action selection，思想源头：Hull 驱力理论、
Maes 行为网络、The Sims 的需求系统）。

## 一句话模型

> 有一个心跳闹钟。每次响，大脑睁眼看一眼世界（多少未读、身体坏没坏、闲了多久），
> 问每个驱力"多疼"，挑最疼的、过了痛阈的、且不在歇息期的那个，去做一件事。
> 没到痛阈就继续睡。**脑子是健忘的，世界是忠实的。**

## 五个角色，一人一个动作

```
宿主 evaluate  → 量世界：看 PENDING/探针，打包成 World 快照（眼睛）
驱力           → 读自己要的感官算疼："我疼 0.83" + "若让我上，指令是这个 prompt"（本能）
DriveArbiter        → 裁决：过滤不达阈值/冷却中的，选最疼的（脑干）
宿主 act       → 动手：拿 prompt 调 agent.run（手）
模型           → 干活（大脑皮层）
```

驱力的两个"无能"：**瞎**（看不到世界，只拿到宿主递来的、自己声明过的那部分感官）、
**无手**（只能报疼和建议，不能行动）。疼不疼是驱力的私事；裁决统一、执行统一。

## 关键决策：拉模型，不是推模型

不是"驱力把事件丢进箱子攒着"，而是心跳时 DriveArbiter **主动轮询**每个驱力。
真相（未读积压、健康状态）存在世界那边，脑子里什么都不存，每次现量。
好处：进程重启不丢事件（重新量就是）、状态永不过期（测量即真值）、
无需队列维护（去重/顺序/上限都不用管）。

World 的形状由宿主声明：`DriveArbiter<W>` 的 W 就是宿主世界的类型。
每个驱力 `Drive<W>` 只要求 W 含自己需要的字段（如 UnreadSenses），
evaluate 收到的 world 即宿主快照本身——类型安全由泛型约束保证。

将来若要处理"绝不能丢的交办任务"，再引入真事件队列与驱力并存：
队列管必须做的，驱力管想做的。

## 三层分工

```
Heartbeat（src/runtime，已有）  心脏：什么时候问（config.heartbeat.intervalMs 调频率）
DriveArbiter（bot/arbiter.ts）          脑干：要不要动、动哪件
agent.run()（模型）             大脑皮层：具体怎么干
```

## 压力公式示例（respond-unread）

```
pressure = clamp01(unreadCount / unreadQuota) × clamp01(age / patienceMs)
```

**相乘 = AND 语义**：数量不够疼 × 时间不够久 = 完全不疼。
刚来的消息不急，攒多了才爆发——"生命感"来自这种对世界的不均匀响应：
坏了立刻跳起来，消息沉得住气，没事时彻底安静（0 模型调用）。

## 扩展指南

- **加驱力**：最容易但会通胀，3~7 个高质量驱力为宜；驱力是消费端，前提是先有对应感官。
  自定义驱力用 `defineDrive<W>({...})`：泛型 W 声明自己需要的感官子集，evaluate 拿到的 world 就只有这些字段。
- **加感官**（扩宿主的 World 类型）：真正的扩容轴。bot 只能被它感知得到的东西驱动；
  World 由宿主定义（`DriveArbiter<W>`），驱力按需挑选，加驱力永不改核心类型。
- **加行动**：不是所有冲动都值得花 token，轻任务可在 act 里纯代码处理。
- **加适应**（质变）：自适应阈值（老没产出就提高痛阈）、效果回写、使命层裁决冲突。

扩展节奏：先接通跑起来 → 看日志调参 → 加第一个真需求驱力 → 最后才碰适应性。

## 三个内置驱力：模板意图

| 驱力 | 本能 | 压力形状 | 模板价值 |
|---|---|---|---|
| `respond-unread` | 渴（社交响应） | 渐变：数量 × 等待，相乘 AND | 渐变响应类的模板 |
| `self-check` | 疼（自保） | 硬开关：坏了恒 1，否则 null | 硬开关类的模板 |
| `self-maintenance` | 无聊（自省） | 时间积累 + 饱和：闲 2h 封顶，6h 冷却 | 时间积累类的模板 |

合成最小生存闭环：对外（有人找→回应）、对内（坏了→修）、对己（闲→自省）。
新驱力照最接近的抄。`self-maintenance` 里"没干过活 = 满压力"是刻意的：
刚出生的 bot 第一件事就该整理自己。

## Drive 字段速查

- `name`：身份证。arbiter 的冷却 Map 以它为 key；同名驱力共享冷却槽；会出现在日志
  和 prompt 前缀里。kebab-case 动词短语（`pending-sweep`）。
- `threshold`：痛阈。压力 >= threshold 才进候选（严格 `<` 淘汰，恰好等于会触发）。
  调它 = 调性格：调高变高冷，调低变热心。与 pressure 是两个数：一个实时测量，一个固定性格。
- `cooldownMs`：不应期。进候选即记录，冷却期内压力再高也没资格。失败重试风暴的限幅器。
  取值锚点：≈ 这件事失败后值得等多久再试一次。秒级=应急重试，分钟级=交互响应，小时级=自维护。
